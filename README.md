# Стенд сценариев

Самостоятельное Vue-приложение для ручной проверки гипотез и фич. В каталоге есть поиск по названию, описанию, дате и slug, фильтр по типу и пагинация по 12 записей. Ветку и прямой адрес сценария можно передать команде.

## Добавление сценария

1. Создай ветку `experiment/<slug>` от актуальной `main`. Используй стабильный slug из строчных латинских букв, цифр и одиночных дефисов.
2. Создай папку `app/src/experiments/<slug>/`. В `manifest.js` экспортируй по умолчанию объект с `title`, `kind` (`'hypothesis'` или `'feature'`), `date` (`YYYY-MM-DD`) и необязательным `summary`. Манифест содержит только метаданные и не импортирует код экрана.
3. Создай `Scenario.vue` в той же папке. Каталог подхватит манифест автоматически, экран загрузится при открытии `/#experiment/<slug>`. Храни модель и демоданные рядом в `model/` и `config/`, когда они нужны.
4. Сверь экран и переходы со спецификацией из Figma и пройденным аудитом библиотеки. Проверь основной путь, применимые ошибки, прямой адрес, перезагрузку и выход обратно в каталог.

```js
export default {
  title: 'Добавление списания баллов Плюса',
  kind: 'hypothesis',
  date: '2026-01-11',
  summary: 'Проверка выбора и подтверждения списания в сценарии заказа.',
};
```

## Как писать код

- Используй Vue SFC с `<script setup>` и локальным SCSS. Размещай представление и события в UI, расчёты и правила переходов в модели, демонстрационные данные в `config/`.
- Соблюдай направление импортов `pages → features → shared`. Для feature используй публичную точку входа `index.js`. Сценарии могут брать общие примитивы и публичные features. Связь маршрута с конкретным сценарием остаётся в корне приложения.
- Используй семантические HTML-элементы, подписи полей, видимый фокус и управление с клавиатуры. Проверяй мобильный размер 375×812, отсутствие переполнения и режим reduced motion.
- Цвета и отступы бери из `app/src/assets/styles/tokens/`. Добавляй семантический токен только при подтверждённой потребности сценария. Укажи его назначение и связь со спецификацией Figma в том же изменении.
- Называй функции по действию, модель тестируй отдельно от DOM. У экспортируемой функции оставь короткий JSDoc у объявления. Опиши назначение и существенные детали контракта. Для неочевидных аргументов и результата добавь `@param` и `@returns`. Укажи исключения, мутацию, сеть и другие побочные эффекты, если они есть.

```js
/**
 * Возвращает доступное количество баллов после применения лимита.
 * @param {number} balance — демонстрационный баланс в целых баллах.
 * @param {number} limit — максимум для текущего заказа.
 * @returns {number} Количество баллов, которое можно списать.
 */
export function availablePoints(balance, limit) {
  return Math.min(balance, limit);
}
```

## Дизайн сценариев

Используй палитры Light/Dark, текстовые классы, отступы, эффекты и шрифты SB Sans из подключённых стилей стенда. Корень сценария получает светлую тему. Для тёмного участка установи `data-theme="dark"` на его контейнер.

Переиспользуй `UiButton`, `UiIcon`, `UiIconButton`, `UiTabBar` и `UiBottomSheet` из `@/shared/ui`. `PhonePreview` принимает композицию экрана через слот по умолчанию. Для жестов, масштаба и reduced motion используй общие composables. Собирай гипотезу в её папке, общие примитивы дополняй только при повторяемой потребности.

## Запрещено

- Копировать продуктовые экраны, состояние и бизнес-логику из продового приложения, подключать его API, аналитику, рабочие аккаунты, секреты и реальные данные. Используй отдельные демоданные.
- Импортировать другой сценарий, обращаться к приватным путям чужой feature, размещать бизнес-логику в шаблоне или обращаться к DOM из расчётов.
- Подставлять сырые цвета и произвольные отступы в UI, дублировать общие примитивы, заменять кнопки и поля картинками.
- Скрывать ошибки, отключать проверки, использовать `skip` или `only` и добавлять зависимости без конкретной причины.
- Пушить эксперименты в репозиторий продукта или самостоятельно сливать экспериментальную ветку в `main` стенда.

## Проверки и публикация

Команды запускай из `app/` на Node.js 22.12 или новее.

```sh
npm ci
npx playwright install chromium
npm run format:check
npm run qa
git diff --check
```

`npm run qa` выполняет модульные тесты, production-сборку и Playwright. После push GitHub Actions повторяет QA. Cloudflare Pages выполняет `npm test && npm run build` и публикует `app/dist/`.

- `main` обновляет [общий каталог](https://testovoe-okryzenie.pages.dev/).
- `experiment/*` получает отдельное превью. Сверь SHA деплоя и статус тестов, затем открой `/#experiment/<slug>` на этом домене.
